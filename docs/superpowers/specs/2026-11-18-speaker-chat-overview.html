Speaker chat plan

Written 2026-11-18 for review. The short version of the two design docs, without code references.

Detail: robin-assistant side and egg server side.

Status on 2026-11-18: the egg server and robin-assistant pieces 1 and 2 are built and tested on their branches. Piece 3 is being built. Nothing has run on the real egg, and nothing is merged.

The problem

The egg talks in the plain web chat, the one the phone uses. So every reminder and task result Robin writes there is spoken, and everything said to the egg shows up in the web chat.

The idea

Speech gets its own chat. Robin knows about both.

Web chatSpeaker chat
How you use itType on the phone or computerTalk to the egg
What Robin does thereWrites textSays it aloud
Where you see itThe chat pageA read-only Speaker page, under the "..." menu
Can you type into itYesNo

How it behaves

Robin knows both chats

Before each turn Robin gets what was said in the other chat since this chat's last turn, up to 10 messages. A tool reads further back. Talk to the egg at 9, type at noon, talk to the egg at 6, and the 6 o'clock turn knows about noon.

Speaking is a choice

Nothing in the web chat is spoken unless Robin chose that. Robin has a Speak tool in the web chat and in a one-person Telegram chat. Projects, threads and Telegram groups do not get it.

A note that is not spoken

When Robin speaks from another chat, it also writes background for whoever answers: where the message came from, why, and what an answer would need. "Yes, tell them five minutes" then makes sense to Robin.

The answer is reported back

When someone answers a spoken message, the chat that sent it is told who answered and what was said.

Unheard becomes text

The egg server already decides whether it may speak: speaking hours, a muted mic, quiet asked for by voice, being offline. Now it reports the result, and anything not spoken is delivered as text. An answer you interrupt arrives as text too.

Approvals go to the phone

A spoken turn that needs an approval or a location puts the card in the web chat, and Robin says so aloud.

Guests

Not handled yet. The speaker chat knows the web chat whoever is speaking. Robin is told not to bring up the web chat aloud unless asked. Security is a later feature.

One field for how a task is delivered

Today a task has deliver (now or later) and urgent. This plan would have added two more. They become one field.

deliverWhat happens when the task fires
textWritten to the chat now
text_laterHeld until you are next around
speakSaid aloud within speaking hours, after a chime
speak_urgentSaid aloud at any hour, ahead of anything waiting, and texted at the same time
chimeThe egg chimes and the words arrive as text

A reminder set by voice defaults to speak. One set by typing defaults to text. Either can ask for the other, so "text me that at five" works when said to the egg. Stored tasks are migrated once. Jobs defined in the config get the same field. The Routines page shows all five choices, and lists reminders set by voice.

What changes for you on day one

  • What you say to the egg stops appearing in the web chat. It appears on the Speaker page.
  • Reminders and task results you set up by typing stop being spoken. They stay text.
  • Every existing reminder becomes text, including the ones set by voice, because they all belong to the web chat today. You tell Robin which should be spoken.
  • Scheduled jobs with no chat, which the egg speaks today, become text unless their config says speak.

Order of work

In robin-assistant, four pieces. Each can ship alone, and nothing changes until the agent's config turns the speaker chat on.

PieceWhatComplexity
1The speaker chat, its read-only page, late answers, outcome reports and the text fallbackMedium to large
2Each chat sees the other, and the tool to read backMedium
3Speak and the single deliver field, with the task migration and the Routines pageLarge
4Reporting answers backSmall

In the egg server, three pieces, deployed together. There is no option to switch between the old path and the new one.

PieceWhatComplexity
1Post to the speaker chat, follow its stream, check at startup that robin-assistant supports itSmall
2Report what became of each message and each unfinished answerSmall to medium
3Late answers, and saying which message an answer is forSmall

The egg server change is deployed only after robin-assistant's piece 2. With piece 1 alone the two chats would know nothing of each other.

Preventing regressions

  • With the speaker chat off in robin-assistant, every request and response there is what it is today, and its existing test suite must pass unchanged. The egg server always uses the speaker chat, so robin-assistant goes first, and going back means reverting the egg server change.
  • Each new behaviour has named tests in the design docs, including the cases the first review found: reloads and crashes with messages pending, two speakers that disagree, an answer cut off mid-sentence, a spoken turn that needs an approval.
  • The task migration keeps reading the old fields for one release, so a reminder cannot be lost between the migration and a restart.
  • A bench check with the real egg comes before daily use: ask a question, type in the web chat, have Robin speak from the web chat, mute the mic, interrupt an answer, answer a spoken question.

Decided

  • Speech has its own chat. This reverses the 2026-11-16 decision to share the web chat.
  • The two chats share recent messages, not one merged history.
  • The speaker chat is visible in the web UI, read-only.
  • Projects and threads cannot speak.
  • One deliver field, and stored tasks are migrated to it.
  • The speaker chat gets no goals and no projects index.
  • The speaker chat's history is summarised and cleared after an hour with no spoken turn.
  • The egg server has no option to switch back to the web chat.
  • A message the egg holds outside speaking hours is texted at once. The egg may still read it out in the morning.
  • An urgent message is always spoken and texted, so it cannot be said to an empty house and lost.
  • The other chat's messages reach Robin as tagged content in the user's turn, marked as a record. They are not given the authority of a system message.

Later

Speaking hours, quiet, presence, holding for morning and "what did I miss?" are rules, and they live in the egg server. They would sit better in Robin, which could then choose text up front. That is a separate, medium-sized move, noted and not planned here.
